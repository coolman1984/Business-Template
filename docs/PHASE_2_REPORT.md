# 🗂️ تقرير المرحلة الثانية — الملفات والحذف والمهام والاسترجاع

## ما الذي بُني؟
| الجزء | ماذا يفعل |
|---|---|
| المهام الخلفية | طابور داخل قاعدة البيانات؛ المهمة تُسجَّل مع العملية نفسها، ويستلمها عامل واحد بمهلة، وأثرها يُحفظ مع إنهائها في نفس اللحظة |
| إعادة المحاولة | الخطأ المؤقت يُعاد بمهلة تكبر تدريجيًا، والخطأ الدائم يتوقف فورًا؛ والمدير يعيد أو يلغي من الشاشة |
| الملفات بإصدارات | كل ملف له إصدارات؛ الإصدار الجديد لا يحل محل القديم إلا بعد فحصه |
| الحجر والفحص | الملف يدخل منطقة حجر، ويُفحص حجمه وبصمته ونوعه الحقيقي من محتواه لا من اسمه؛ الملفات التشغيلية والمضغوطة والمحتوى النشط مرفوضة |
| التنزيل الآمن | بصلاحية فرع الطلب، ويُسجَّل، ويُرسل كمرفق لا يُفتح داخل المتصفح |
| سلة المحذوفات | حذف الطلب (المسودة) والملف بسبب مكتوب، واسترجاعهما بنفس البيانات والسجل؛ الملف لا يرجع قبل طلبه |
| أرشيف سجل المراجعة | سلسلة مترابطة لكل شركة تُحفظ خارج القاعدة بنقاط تحقق موقّعة؛ أي تعديل أو حذف أو بتر يُكشف |
| النسخ الاحتياطي | نسخة متسقة للبيانات والملفات مع بيان يفحص نفسه؛ الاسترجاع يرفض نسخة تالفة ولا يكتب فوق قاعدة موجودة |
| الشاشات | مرفقات كل طلب بإصداراتها، سلة المحذوفات، والمهام الخلفية — والأزرار حسب الصلاحية |
| تشغيل بضغطة | `start-webapp.bat` (ويندوز) و`start-webapp.command` (ماك ولينكس): قاعدة بيانات خاصة داخل المشروع، وبيانات تجريبية، وتحديث تلقائي للشاشة أثناء التطوير |

## اختبارات الخروج من الخطة (كلها ناجحة)
| الشرط | الدليل |
|---|---|
| موت عامل لا يضاعف نتيجة | عامل يتوقف في منتصف المهمة ← تُعاد بعد انتهاء مهلته وأثرها يُطبَّق مرة واحدة؛ وعامل فقد مهلته لا يُنهي شيئًا؛ وعدة عمال متنافسين لا يشغّلون مهمة مرتين |
| فشل استبدال ملف لا يحذف القديم | إصدار جديد مرفوض ← الإصدار الحالي يبقى كما هو؛ وحتى لو انتهى فحص إصدارين بترتيب معكوس يبقى الأحدث هو الحالي |
| الاسترجاع يعيد بيانات وملفات وصلاحيات صالحة | نسخة ← استرجاع في بيئة جديدة تمامًا ← تشغيل النظام عليها: الدخول، تنزيل الملف، الصلاحيات، العزل بين الشركات، واستمرار الترقيم كلها سليمة |
| فشل سجل حساس يمنع الاعتماد | أي أمر يغيّر سجلًا دون أثر مراجعة يُلغى بالكامل (من المرحلة الأولى)، وكل عمليات هذه المرحلة تمر من نفس البوابة |

**الأرقام:** ٩٨ اختبارًا ناجحًا (كانت ٦٦).
**تجربة حقيقية:** في متصفح حقيقي: رفع ملف ← فحصه ← إصدار جديد ← رفض ملف تشغيلي متنكر ← تنزيل ← حذف الملف ثم الطلب ← استرجاعهما من السلة ← متابعة المهام. وجُرّبت بثلاثة أدوار مختلفة للتأكد من ظهور الأزرار الصحيحة فقط.

## قرارات
- **مكتبة قاعدة بيانات مدمجة للتطوير فقط** (`embedded-postgres` برخصة MIT، وقاعدة البيانات نفسها برخصة PostgreSQL المفتوحة): الضرورة أن يشغّل غير المتخصص النظام بضغطة دون تثبيت خادم قاعدة بيانات. لا تُستخدم في التشغيل الفعلي.
- **النسخ الاحتياطي والأرشفة بلا شاشة عمدًا:** تحتاج حساب مالك قاعدة البيانات، والتطبيق ممنوع من استخدامه (قاعدة ثابتة). تُشغَّل بأوامر من الجهاز نفسه أو بجدولة.

## حدود معلنة
- الفحص يتحقق من النوع الحقيقي والمحتوى النشط، لكنه ليس برنامج مكافحة فيروسات؛ ربط برنامج فحص خارجي مكانه جاهز.
- الحذف النهائي من السلة بعد مدة غير مبني بعد.
- أمر التشغيل بضغطة جُرّب على لينكس فقط؛ ملف ويندوز وماك لم يُجرّبا على جهاز حقيقي.
- ما زال ناقصًا من المرحلة الأولى: دعوة موظف من الشاشة، استعادة كلمة المرور، الخطوة الثانية للمدير، وموافقة شخص ثانٍ.
