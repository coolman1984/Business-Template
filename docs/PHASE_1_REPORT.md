# 🔐 تقرير المرحلة الأولى — الهوية والأدوار وبوابة الأوامر

## ما الذي بُني؟
| الجزء | ماذا يفعل |
|---|---|
| دخول حقيقي | مكتبة هوية معتمدة (رخصة مفتوحة): بريد وكلمة مرور، جلسات يمكن إنهاؤها فورًا، والتسجيل الذاتي مقفول |
| فصل الهوية عن الأعمال | المكتبة لها حساب قاعدة خاص لا يرى بيانات الشركات، وحساب التشغيل لا يرى كلمات المرور |
| اختيار الشركة | الشخص يختار من شركاته هو فقط، ويمكنه التبديل بينها؛ لا يستطيع اختيار عضوية غيره |
| سجل القدرات | قائمة رسمية بكل عملية؛ لا أمر ولا صلاحية لشيء غير مسجل فيها |
| أدوار جاهزة | مدير الشركة، مدير فرع، أمين مخزن، مراجع — تُعيَّن لفرع أو أكثر أو لكل الشركة |
| استثناءات شخصية | سماح أو منع لشخص بعينه؛ المنع يغلب دائمًا |
| سقف التفويض | المدير لا يمنح إلا ما يملكه هو وفي نفس النطاق |
| حماية من الخطأ الذاتي | لا أحد يعدّل صلاحياته أو يوقف نفسه؛ ولا يمكن ترك الشركة بلا مدير |
| إيقاف المستخدم | يسري فورًا على كل جلساته |
| حارس القاعدة | أي كتابة لا تمر ببوابة الأوامر ترفضها القاعدة نفسها، حتى من حساب المالك |
| أثر مطابق لكل كتابة | القاعدة تدوّن كل سجل تغيّر، والبوابة ترفض الحفظ لو سجل تغيّر بلا أثر مراجعة |
| العمليات الحساسة | الاعتماد وتغيير الصلاحيات يُرفضان لو تغيرت صلاحياتك بعد فتح الصفحة |
| حماية المتصفح | طلب تعديل قادم من موقع آخر يُرفض |
| شاشة الصلاحيات | مستخدمون، أدوار، استثناءات، جدول النتيجة الفعلية لكل فرع مع السبب، وتجربة «هل يستطيع؟» |
| شاشة الطلبات | إنشاء واعتماد، والأزرار تظهر حسب الصلاحية |

## اختبارات الخروج من الخطة (كلها ناجحة)
| الشرط | الدليل |
|---|---|
| كل قدرة جديدة تظهر في سجل الصلاحيات | أمر يطلب قدرة غير مسجلة يُرفض عند التشغيل؛ ومنح قدرة مجهولة يُرفض |
| أي مسار كتابة غير مسجل يفشل | كتابة بلا بوابة ← مرفوضة؛ أمر يغيّر سجلًا لم يبلّغ عنه ← مرفوض؛ جدول جديد بلا حارس ← الاختبار يفشل |
| تغيّر السياسة أثناء الجلسة يوقف العملية الحساسة | اعتماد مبني على صلاحيات قديمة ← مرفوض؛ وسحب الدور مع ٥ اعتمادات متزامنة ← لا اعتماد بعد السحب |
| كل كتابة ناجحة لها أثر مطابق | فحص تلقائي قبل الحفظ في كل أمر |

**الأرقام:** ٦٦ اختبارًا ناجحًا، وكسرنا ٧ حمايات جديدة عمدًا فمسكتها الاختبارات كلها.
**تجربة حقيقية:** شُغّل النظام كاملًا في متصفح: دخول، إنشاء طلب، شاشة الصلاحيات، وتجربة «هل يستطيع؟».

## حدود معلنة
- لا يوجد بعد: دعوة مستخدم جديد من الشاشة، استعادة كلمة المرور، تحقق إضافي للمدير (خطوة ثانية).
- موافقة شخص ثانٍ على الصلاحيات القوية غير مبنية بعد.
- إنشاء أدوار جديدة من الشاشة غير متاح؛ تعديل صلاحيات دور موجود متاح عبر الواجهة البرمجية فقط.
- تشغيل الحاويات مكتوب ولم يُجرب داخل حاوية.

## التالي: المرحلة الثانية
الملفات بإصدارات، سلة المحذوفات والاسترجاع، المهام الخلفية، النسخ الاحتياطي واستعادته في بيئة جديدة.
